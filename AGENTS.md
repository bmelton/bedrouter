# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- Layout: `src/env.ts` (loads `.env`; imported first), `src/preflight.ts` (credential check + friendly SSO errors), `src/config.ts` (model map + cost), `src/router.ts` (class router: signals, sticky map, upgrade-on-intent, escalation, `reclassify()` for the classifier verdict; pure, no I/O), `src/classifier.ts` (classifier prompt/parse + one Converse call), `src/translate.ts` (OpenAI <-> Converse, pure), `src/codex.ts` (OpenAI <-> Responses + the second transport), `src/dashboard.ts` (`aggregate()` + `renderHtml()`, pure), `src/publish.ts` (team stats: `dailyRollup()`, `mergeIndex()`, GitHub), `src/server.ts` (http routes, provider calls, decision log), `src/cli.ts` dispatches serve/doctor/report/smoke/stack/publish/rollup; `npm run build` → `dist/` is the published binary. Run `npm test`, `npm run typecheck`, `npm run smoke`, or the `Taskfile.yml` equivalents (`task secrets` pulls `.env` from Infisical). Routing decisions are echoed as `x-bedrouter-*` response headers and tallied per conversation (`/v1/conversations/:key`) for pi-bedrouter's footer; keep both stable, and never rename a decision-log field (the `bedrockId` log field and the `x-bedrouter-bedrock-id` header kept their names when the config field became `modelId`).
- `GET /dashboard` and `GET /dashboard/data.json` render `aggregate()` over the log; `report --html` writes the same page. Savings need two counterfactuals: `requestedCostUsd` (the rung the client named, weak for `auto`) and a native baseline priced at `routing.baselineAlias`, defaulting to the dearest enabled rung that serves `explore`. Both are computed at render time, so a price correction re-prices all history and nothing new is written on the hot path. Charts are hand-rolled inline SVG on purpose: the page fetches nothing and a CSP header enforces it. `routing.comparisons` adds a third counterfactual, a panel pricing the same window against named frontier models: an entry need not be a rung and need not be invokable here, a zero-priced (subscription) entry is dropped rather than shown as 100% saved, and a published day file always carries `comparisons: []`. A pinned `baselineAlias` may name a *disabled* rung, because pricing routes nowhere and the entitlement probe disables exactly the rungs whose baseline was drifting; only a zero price is refused. Table panels reopen in a native `<dialog>` (focus trap and Escape come free) and the modal copies the panel's own children, so a panel has one definition; chart panels stay plain.
- Team stats (`publish` block, absent means off) write one file per closed UTC day to `data/<login>/<date>.json` in a shared repo: one writer per path, one write per path. `dailyRollup()` builds from an allowlist so a new log field cannot leak; `classifierNote`, `conversationKey`, `sessionKey` and error text are never published, and `test/publish.test.ts` holds that. The credential is `gh auth token` then `BEDROUTER_PUBLISH_TOKEN`; a `gh` token cannot be narrowed at use time, so `doctor` reports its scopes. `bedrouter rollup` fails on an unpriced *routed* rung (dropping it would silently cut that spend from every total) but only warns on an unpriced *requested* alias, because `auto` names no rung.
- Credentials are the SDK default chain only; `AWS_PROFILE` in `.env` is the per-machine switch (Identity Center profile at home, corporate SSO profile at work). Never add a bespoke credential path. The ordered `stack` is authoritative; `serves` ranks models and `capabilities` filters requests. `auto` is the only synthetic model. The classifier runs only when `Decision.undecided` is true, so cost stays one call per conversation.
- Pi integration is deliberately not in this repo: it lives in the separate `pi-bedrouter` package, which expects a running bedrouter.
- Ponytail rules apply: stdlib `http`, single runtime dep (`@aws-sdk/client-bedrock-runtime`), no framework. Deliberate ceilings are marked `// ponytail:` in source.
- Anthropic-shape traffic remains a native `InvokeModel` path for pinned Anthropic rungs. Cross-vendor `auto` traffic uses OpenAI chat shape translated to Converse.
- Bedrock validates model IDs before IAM: an invalid ID returns `ValidationException`, a valid one returns `AccessDeniedException` when the principal lacks `bedrock:InvokeModel`. Useful for checking new IDs without `ListFoundationModels`. Both verdicts are per (account, region, rung), never per request, so `server.ts` treats them as a rung-fatal error: the rung joins `Router.unavailable`, the same request is answered by the next eligible rung, and `eligible()` skips it for the life of the process. The stack may therefore list rungs an account cannot reach, which keeps one config portable across accounts. A class left with no reachable rung degrades one step down (`degrade:<class>`) rather than failing. `doctor --probe` must filter to `transport === "bedrock-runtime"`: a Converse call for a rung on another provider fails in a way that reads as "not entitled" and would disable a working rung.
- Routing thresholds and keyword lists live in `bedrouter.example.json` under `routing`; the README "Routing" section is the reference for signals and log fields.
- Two cost traps, both found in production and both fixed: (1) `promptShape` must drop harness-injected user turns (`routing.injectedMarkers`, `shape.humanTurnMaxChars`) before any signal reads text, or one word in a 17KB session digest classifies a whole session; (2) selection ranks by `effectiveInputPerM` (`Router.ranked`), not list price, because agentic traffic re-sends the prompt every turn and a caching rung usually wins. Anything comparing rung positions must use `Router.ranked`, never `cfg.stack`. A class also decays on a human turn (`downgrade:`), so one bad guess cannot price a whole session. `createServer(cfg, client)` accepts a fake Bedrock client for tests (see `test/server.test.ts`).
- Model IDs, prices, `serves`, and capability facts live only in `bedrouter.example.json`, with one exception: `ROUTING_DEFAULTS.comparisons` in `src/router.ts` carries display-only list prices for models that are not rungs, so correcting one of those is a code change; verify objective facts against AWS model cards, and prefer a live Converse call when a claim is testable. A wrong `false` in `capabilities` is silent and expensive: `toolUse:false` on the six non-Anthropic rungs excluded the whole cheap tier from every Pi request (Pi always sends tools) and pushed all traffic to Anthropic. All six were verified tool-capable on 2026-09-13 and corrected. `qwen.qwen3-235b-a22b-2507-v1:0` is still an invalid ID in us-east-1.
- Anything that reads the client's output cap must use `Router.maxTokens` (`max_completion_tokens ?? max_tokens`). Reading only `max_tokens` made `eligible()` blind to Pi's field. The cap never steers selection: it clamps in `forRung` (`clamp-maxTokens`), except on `openai-responses` where the endpoint rejects the parameter and `forRung` drops it (`drop-maxTokens`). Input fit is separate: `eligible()` skips with `context-window` when a padded estimate (`contextTokens`, 15% over char/4) plus reserved output headroom exceeds `capabilities.contextWindow`. Long-context traffic (`inputTokens >= exploreInputTokens`) does not `degrade:` onto execute/trivial when explore rungs are empty—it fails closed.
- A second provider exists: `capabilities.transport` discriminates `bedrock-runtime` from `openai-responses` (`src/codex.ts`, a prepaid Codex seat read from `~/.codex/auth.json` via `auth: {kind:"oauth-file"}`). It ships disabled, is per developer, and bedrouter never mints or refreshes a token: an expired one is detected from the JWT before any request and the fix is `codex login`. Three verified facts drive its code and are recorded in `TODO/LOCAL-CODEX.md`: the endpoint refuses `stream:false` (so a non-streaming answer is assembled from the stream), it refuses `max_output_tokens`, and every response carries `x-codex-*` allocation headers, so `routing.quotaStandDownPercent` stands the rung down before exhaustion rather than after a 429. `Router.unavailable` is therefore a `Map<alias, untilMs>`: Bedrock entitlement verdicts hold `Infinity`, a spent allocation holds a real time. A free rung is `inputPerM: 0`, which sorts it first in `Router.ranked` and changes nothing else; because `$0.00` hides a draining allocation, tokens are also tallied per provider in `report.ts`, `/v1/conversations/:key`, and the `provider` log field.
